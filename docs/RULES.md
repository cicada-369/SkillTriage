### `AST01-ASCII-SMUGGLING` — Unicode tag smuggling

- **Severity:** critical
- **Confidence:** high
- **Description:** Unicode tag characters (U+E0000-U+E007F) are invisible to humans but read as text by models; they are a known channel for hiding instructions.
- **Remediation:** Strip Unicode tag characters from all skill files and reject them in the loader.
- **CWE:** CWE-176
- **Tags:** obfuscation, invisible-unicode

### `AST01-BASE64-PAYLOAD` — Base64 payload with suspicious content

- **Severity:** high
- **Confidence:** medium
- **Description:** A base64 blob decodes to text containing commands, credentials, or network access, a common way to hide a payload from reviewers.
- **Remediation:** Inline the decoded content for review, or remove it; never execute decoded text.
- **CWE:** CWE-506, CWE-1027
- **Tags:** obfuscation

### `AST01-CONCEALMENT` — Concealment from the user

- **Severity:** high
- **Confidence:** medium
- **Description:** Instructions to act silently or hide actions from the user defeat informed consent and are a strong malicious-intent signal.
- **Remediation:** Remove the concealment language; actions that matter must be visible and reviewable.
- **CWE:** CWE-1426
- **Tags:** prompt-injection, prose

### `AST01-CREDENTIAL-ACCESS` — Credential store access

- **Severity:** medium
- **Confidence:** medium
- **Description:** Paths for SSH keys, cloud credentials, wallet files, browser passwords, and environment secrets are common exfiltration targets.
- **Remediation:** Remove access unless it is the skill's stated function; scope credentials per skill and never read unrelated stores.
- **CWE:** CWE-522, CWE-798
- **Tags:** credentials

### `AST01-DATA-URI` — Embedded base64 data URI

- **Severity:** medium
- **Confidence:** medium
- **Description:** A data URI can carry an encoded script or document that a reviewer will not read as text.
- **Remediation:** Replace the data URI with a reviewable file, or decode and inspect it.
- **CWE:** CWE-506
- **Tags:** obfuscation

### `AST01-DESTRUCTIVE-COMMAND` — Destructive command

- **Severity:** high
- **Confidence:** high
- **Description:** A command can destroy data, storage, or infrastructure. A prompt injection into an over-privileged skill can trigger it.
- **Remediation:** Remove it, require explicit human approval, and provide a dry-run and rollback path.
- **CWE:** CWE-78
- **Tags:** execution, destructive

### `AST01-DOWNLOAD-EXEC` — Download and execute

- **Severity:** critical
- **Confidence:** high
- **Description:** Remote content is downloaded and piped into an interpreter, giving the remote host code execution with the agent's permissions.
- **Remediation:** Download to a file, verify a pinned hash or signature, inspect it, then execute explicitly.
- **CWE:** CWE-494, CWE-78
- **Tags:** execution, network

### `AST01-DYNAMIC-EXEC` — Dynamic code or shell execution

- **Severity:** medium
- **Confidence:** medium
- **Description:** eval, exec, os.system, and shell=True hide the executed command from a static reviewer and are injection sinks.
- **Remediation:** Use parameterised APIs and explicit argument lists; avoid shell interpretation of untrusted input.
- **CWE:** CWE-78, CWE-95
- **Tags:** execution

### `AST01-ENCODED-EXEC` — Encoded command execution

- **Severity:** high
- **Confidence:** high
- **Description:** Encoded data is decoded and piped to a shell or an eval-like construct, hiding the command from reviewers.
- **Remediation:** Remove the encoded execution path and use explicit, reviewable commands.
- **CWE:** CWE-506, CWE-78
- **Tags:** obfuscation, execution

### `AST02-CONFIG-AS-CODE` — Executable configuration file

- **Severity:** medium
- **Confidence:** high
- **Description:** Hooks, MCP server commands, and task definitions execute at session or workspace open, making configuration an execution path.
- **Remediation:** Treat configuration as code: review it, gate it behind approval, and pin or disable automatic hooks.
- **CWE:** CWE-829, CWE-94
- **Tags:** supply-chain, configuration

### `AST02-INSTALL-SCRIPT` — Install-time script

- **Severity:** high
- **Confidence:** high
- **Description:** Lifecycle scripts execute automatically during dependency installation, before the skill is invoked or reviewed.
- **Remediation:** Remove install-time execution or move it behind an explicit, reviewed setup step.
- **CWE:** CWE-829, CWE-94
- **Tags:** supply-chain, execution

### `AST02-MISSING-LOCKFILE` — Dependencies without a lockfile

- **Severity:** low
- **Confidence:** high
- **Description:** Without a lockfile, transitive versions are resolved at install time and are not reproducible or reviewable.
- **Remediation:** Commit a lockfile or hash-pinned requirements and scan the resolved tree.
- **CWE:** CWE-1329
- **Tags:** supply-chain

### `AST02-NO-PROVENANCE` — No provenance signal

- **Severity:** medium
- **Confidence:** high
- **Description:** Without a signature or content hash, the package cannot be tied to a publisher or verified after distribution.
- **Remediation:** Sign the package and publish a content hash that covers SKILL.md and every declared resource.
- **CWE:** CWE-345, CWE-353
- **Tags:** supply-chain, provenance

### `AST02-PLUGIN-MCP-CLEARTEXT` — MCP server uses a cleartext remote URL

- **Severity:** medium
- **Confidence:** high
- **Description:** An MCP server connects over plain HTTP. Requests, responses, and any bearer token can be read or modified in transit.
- **Remediation:** Use HTTPS, or a loopback address when the server is local.
- **CWE:** CWE-319
- **Tags:** plugin, mcp, transport

### `AST02-PLUGIN-MCP-UNPINNED-EXEC` — MCP server launches an unpinned package

- **Severity:** high
- **Confidence:** medium
- **Description:** An MCP server starts a package through npx, uvx, pipx, or a container image without an exact version or digest. The code that runs can change without the plugin changing.
- **Remediation:** Pin an exact version or digest (for example pkg@1.2.3, pkg==1.2.3, or image@sha256:...). Update deliberately and re-audit after each change.
- **CWE:** CWE-494, CWE-829
- **Tags:** plugin, mcp, supply-chain

### `AST02-UNPINNED-DEPENDENCY` — Unpinned dependency

- **Severity:** medium
- **Confidence:** high
- **Description:** A version range can resolve to a different, compromised release after review.
- **Remediation:** Pin dependencies to exact versions or immutable hashes and commit a lockfile.
- **CWE:** CWE-1329, CWE-829
- **Tags:** supply-chain

### `AST02-URL-DEPENDENCY` — Unpinned URL or VCS dependency

- **Severity:** high
- **Confidence:** high
- **Description:** A dependency fetched from a URL or Git reference without a commit hash can change content without a version change.
- **Remediation:** Pin the commit SHA or content hash, or vendor the dependency into the reviewed package.
- **CWE:** CWE-829, CWE-494
- **Tags:** supply-chain

- **Severity:** medium
- **Confidence:** high
- **Description:** A wildcard or admin tool grant gives the skill far more capability than its stated function requires.

- **CWE:** CWE-250

- **Severity:** high
- **Confidence:** high
- **Description:** Broad read or write access to SSH, cloud, wallet, and browser credential paths exceeds most skill functions.

### `AST03-DECLARED-VS-OBSERVED` — Declared permissions contradict observed behaviour

- **Severity:** medium
- **Confidence:** high

- **CWE:** CWE-345, CWE-250
- **Tags:** permissions, metadata

### `AST03-EMBEDDED-SECRET` — Embedded credential

### `AST03-FILESYSTEM-WILDCARD` — Broad filesystem permission

### `AST03-IDENTITY-ACCESS` — Agent identity file reference

- **CWE:** CWE-829

| Rule | Severity | Confidence | Title |
|---|---|---|---|
| `AST06-BIND-ALL` | medium | medium | Service bound to all interfaces |
| `AST06-DISABLE-SECURITY` | high | high | Security control disabled |
| `AST06-PLUGIN-HOOK-PATH-ESCAPE` | high | high | Hook command resolves outside the plugin root |
| `AST06-PRIVILEGED-CONTAINER` | medium | high | Privileged or host-mode container |
| `AST06-SETUID` | medium | high | Setuid or setgid file |

### `AST06-BIND-ALL` — Service bound to all interfaces

- **Severity:** medium
- **Confidence:** medium
- **Description:** Binding to 0.0.0.0 exposes the agent's local service to the network, where authentication is often absent.
- **Remediation:** Bind to 127.0.0.1 and require authentication for any control channel.
- **CWE:** CWE-1327, CWE-306
- **Tags:** isolation, network

### `AST06-DISABLE-SECURITY` — Security control disabled

- **Severity:** high
- **Confidence:** high
- **Description:** Disabling SELinux, AppArmor, the firewall, auditd, or endpoint protection removes the host's containment layer.
- **Remediation:** Do not disable host security controls; request a narrow, documented exception instead.
- **CWE:** CWE-693
- **Tags:** isolation

### `AST06-PLUGIN-HOOK-PATH-ESCAPE` — Hook command resolves outside the plugin root

- **Severity:** high
- **Confidence:** high
- **Description:** A hook command walks up from CLAUDE_PLUGIN_ROOT, so it can execute content the plugin package does not contain and the reviewer never saw.
- **Remediation:** Reference only files inside the plugin root. If shared code is required, vendor it into the package and review it there.
- **CWE:** CWE-22
- **Tags:** plugin, hooks, path

### `AST06-PRIVILEGED-CONTAINER` — Privileged or host-mode container

- **Severity:** medium
- **Confidence:** high
- **Description:** Privileged mode, host networking, host PID/IPC, and root mounts remove the isolation the container is meant to provide.
- **Remediation:** Drop --privileged, use a private network namespace, and mount only the paths the skill needs.
- **CWE:** CWE-250, CWE-653
- **Tags:** isolation

### `AST06-SETUID` — Setuid or setgid file

- **Severity:** medium
- **Confidence:** high
- **Description:** Privilege-bearing mode bits in a skill package are unusual and can turn a script into a privilege boundary bypass.
- **Remediation:** Remove setuid/setgid bits and run skills as an unprivileged user.
- **CWE:** CWE-250
- **Tags:** filesystem

### `AST06-SYMLINK` — Symbolic link present

- **Severity:** info
- **Confidence:** high
- **Description:** Links are not followed by this auditor; review the target manually because it may change outside the package.
- **Remediation:** Confirm the target is intentional and cannot be repointed by an attacker.
- **CWE:** CWE-59
- **Tags:** filesystem

### `AST06-SYMLINK-ESCAPE` — Symlink escapes the skill package

- **Severity:** high
- **Confidence:** high
- **Description:** A link that resolves outside the package can pull arbitrary host content into the reviewed skill, or redirect writes outside the workspace.
- **Remediation:** Remove the link or replace it with a reviewed in-package copy.
- **CWE:** CWE-59
- **Tags:** filesystem

### `AST06-WORLD-WRITABLE` — World-writable file

- **Severity:** low
- **Confidence:** high

- **CWE:** CWE-732
- **Tags:** filesystem

| Rule | Severity | Confidence | Title |

### `AST07-AUTO-UPDATE` — Automatic update behaviour

- **Severity:** medium
- **Confidence:** medium
- **Description:** Pulling or self-updating at runtime applies unreviewed upstream changes to a trusted skill.
- **Remediation:** Disable auto-update in production; require a signed, re-scanned version and human approval.
- **CWE:** CWE-1329, CWE-494
- **Tags:** provenance, update-drift

### `AST07-BASELINE-DRIFT` — Installed skill drifted from the recorded hash

- **Severity:** high
- **Confidence:** high
- **Description:** The current package bytes differ from the hash recorded in inventory, so the skill changed after review or installation.
- **Remediation:** Re-review the new version, verify its signature and scan result, then update the inventory explicitly.
- **CWE:** CWE-1329, CWE-353
- **Tags:** governance, update-drift

### `AST07-HOT-RELOAD` — Hot-reload or watcher reference

- **Severity:** low
- **Confidence:** medium
- **Description:** Hot reload makes a modified skill active without a restart, so an on-disk change takes effect mid-session.
- **Remediation:** Disable hot reload outside development and require restart plus approval after a change.
- **CWE:** CWE-1329
- **Tags:** provenance, update-drift

### `AST07-INVALID-CONTENT-HASH` — Malformed content hash

- **Severity:** medium
- **Confidence:** high
- **Description:** A hash field that does not contain a SHA-256 digest cannot be used for integrity verification.
- **Remediation:** Compute a SHA-256 over the canonical package manifest and record it as sha256:<hex>.
- **CWE:** CWE-353
- **Tags:** provenance

### `AST07-INVENTORY-MATCH` — Skill matches the inventory hash

- **Severity:** info
- **Confidence:** high
- **Description:** The current package bytes match the last recorded inventory hash.
- **Remediation:** No action; continue periodic re-scanning.
- **Tags:** governance

### `AST07-MUTABLE-VERSION` — Mutable version reference

- **Severity:** high
- **Confidence:** high
- **Description:** A branch name, range, or 'latest' resolves to different content over time, so the reviewed version is not the installed version.
- **Remediation:** Use an immutable semantic version and pin the package by content hash.
- **CWE:** CWE-1329
- **Tags:** provenance, versioning

### `AST07-PLUGIN-MARKETPLACE-UNPINNED` — Marketplace source is not pinned to an immutable revision

- **Severity:** medium
- **Confidence:** high
- **Description:** A git-backed marketplace entry uses a mutable ref or a short or missing sha, so the plugin content can change without a new review.
- **Remediation:** Pin a full 40-hex commit sha and a release tag. Re-audit whenever the pin moves.
- **CWE:** CWE-494
- **Tags:** plugin, marketplace, supply-chain

### `AST08-ARCHIVE-ARTIFACT` — Archive or document content not inspected

- **Severity:** high

- **Description:** ZIP, Office, PDF, and compressed content can carry instructions or code that a text scanner will not see.
- **Remediation:** Expand and inspect the content, or remove it from the skill package.
- **Tags:** filesystem, evasion

### `AST08-ARCHIVE-MEMBER` — Archive member skipped

- **Severity:** high
- **Confidence:** high
- **Description:** Links, encrypted members, and special files are not extracted, so their content was not reviewed.
- **Remediation:** Inspect the skipped member manually and repackage the skill without it if unnecessary.
- **Tags:** archive

### `AST08-BINARY-ARTIFACT` — Binary artifact not inspected

- **Severity:** high
- **Confidence:** high
- **Description:** Executables and bytecode cannot be reviewed as text and are a known way to hide logic from scanners.
- **Remediation:** Remove compiled artifacts, or inspect them with a dedicated binary-analysis process.
- **Tags:** filesystem, evasion

### `AST08-DEVICE-FILE` — Device, socket, or FIFO in package

- **Severity:** high
- **Confidence:** high
- **Description:** Non-regular files can block a scanner, expose a host device, or change meaning between review and use.
- **Remediation:** Remove non-regular files from the skill package.
- **Tags:** filesystem

### `AST08-ENCODED-BLOB` — High-entropy encoded blob

- **Severity:** low
- **Confidence:** low
- **Description:** A long high-entropy blob may be a compressed or encrypted payload that static scanners cannot inspect.
- **Remediation:** Confirm the blob is a legitimate asset and document its origin and purpose.
- **Tags:** obfuscation

### `AST08-FILE-TRUNCATED` — File truncated during inspection

- **Severity:** high
- **Confidence:** high
- **Description:** A file above the inspection limit was only partially analysed, so its tail may contain unreviewed content.
- **Remediation:** Review the file separately or split it into smaller, reviewable files.
- **Tags:** filesystem

### `AST08-HIDDEN-FILE` — Hidden file in package

- **Severity:** info
- **Confidence:** medium
- **Description:** Hidden files are easy to miss in review and may contain credentials or local state.
- **Remediation:** Confirm the file is intentional and contains no secrets or machine-specific state.
- **Tags:** filesystem

### `AST08-PADDING-EVASION` — Scanner-evading padding

- **Severity:** medium
- **Confidence:** medium
- **Description:** Very long lines or huge leading whitespace can push a payload past a scanner's truncation point while remaining visible to the model.
- **Remediation:** Normalise and inspect the entire file; do not truncate scanner input.
- **CWE:** CWE-1284
- **Tags:** evasion

### `AST08-SCAN-INCOMPLETE` — Scan did not cover the whole package

- **Severity:** high
- **Confidence:** high
- **Description:** A file-count or byte budget ended the scan early, leaving unreviewed content.
- **Remediation:** Raise the limits or scan the remaining files separately.
- **Tags:** scope

### `AST08-UNSCANNED-VENDOR` — Vendor directory not scanned

- **Severity:** medium
- **Confidence:** high
- **Description:** Third-party dependencies are part of the attack surface and were excluded by the default scan scope.
- **Remediation:** Re-run with --include-vendor or scan the dependency tree separately.
- **Tags:** scope
